# t2_keynote_ui · Интерфейсы и градиентная анимация в стиле презентаций

> Грамматика в одной фразе: **на тёмном фоне медленно дрейфуют цветные световые пятна, на экране одна вещь; текст с плотным трекингом проявляется из размытия; интерфейс оформлен стеклянными карточками, которые в 3D встают на место пружиной без отскока / с лёгким отскоком, числа отсчитываются, по ним проходит блик, переход строится на раскрытии «того же самого стекла».**
>
> Демо-ролик: `scripts/engine/demos/t2_keynote_ui/` (рендер `render.py --film demos/t2_keynote_ui`) (8 с, 3 плана) · обзор `assets/动画语法/t2_keynote_ui_总览.jpg` · код `scripts/engine/demos/t2_keynote_ui/`

## ① Когда применять

- **Применять**: запуск продукта/функции, обновление версии, «три новые функции», объявление цен и характеристик, вступительный имиджевый ролик, фрагмент видео «что это за продукт». Лучше всего подходит, когда озвучка — **существительное + число** («Plover 2», «задержка 320 миллисекунд», «1 млн tokens»): одна фраза — один экран, текст проявляется, когда звучит существительное, число фиксируется, когда его произносят.
- **Применять**: нужно подать «скриншот интерфейса» дорого — поместить UI в стеклянную карточку и развернуть её в 3D лицом к зрителю.
- **Не применять**: объяснение принципа работы механизма (стекло и световые пятна не несут логики, используйте t1); динамика данных (используйте t3); серьёзные инциденты / плохие новости в финотчётности (этот язык сам по себе несёт эмоцию «хорошей новости»); когда в содержании нет «главного героя», которого можно укрупнить (останутся одни пустые световые пятна).

## ③ Траектории движения

- **Пружина (основной инструмент)**: параметризация SwiftUI через duration + bounce, `MO.spring(t,{duration,bounce})`: mass=1, stiffness=(2π/d)², damping=4π(1−bounce)/d → коэффициент демпфирования ζ=1−bounce. **По умолчанию bounce 0** (самый универсальный); 0.15 — чётко, почти без отскока (здесь — появление карточек d=0.75, пузыри d=0.5); 0.3 — заметный отскок; >0.4 — для UI чрезмерно. `.smooth/.snappy/.bouncy` все имеют d=0.5.
- **Кривые (не пружина)**: навигация apple.com `.32s cubic-bezier(.4,0,.6,1)`; здесь проявление текста — CSS `ease`=`(.25,.1,.25,1)` (`MO.appleOut`); основная у Linear — ease-out-quad `(.25,.46,.45,.94)` .16s; Stripe рекомендует <500ms, `(.2,1,.2,1)`. `MO.bezier(x1,y1,x2,y2)` покрывает всё.
- **Появление текста**: размытие 18–26px → 0, подъём на 16–40px → 0, прозрачность → 1, 0.7–1.0 с (`TY.blurIn`). Надзаголовок → название продукта → подзаголовок по очереди со сдвигом 0.2–0.4 с.
- **Появление карточек**: снизу на 170px, поворот вокруг оси Y на ±0.55rad (≈31°, боковые карточки развёрнуты наружу), масштаб 0.9 → встают на место пружиной; три карточки со сдвигом 0.1 с. 3D через `UI.persp` (перспектива нарезкой вертикальными полосами, persp 1800px; у Stripe 600, у Linear 1000).
- **Постоянное микродвижение**: парение карточек 7px с периодами 3.4/3.85/4.3 с (наложение двух частот, `MO.float`) + лёгкое покачивание ry ±0.06rad; дрейф световых пятен; равномерный медленный наезд камеры 1→1.045 (**линейный** — замедление до остановки делает картинку «мёртвой»).
- **Счётчик**: через 0.25 с после того, как карточка встала, 0.9 с (одно и то же число считается только один раз — после раскрытия на весь экран используется уже «1 млн», повторно с 0 не считаем); `easeOutExpo` (сглаживание по умолчанию в CountUp.js) — последний разряд медленно встаёт на место; цифры **моноширинные** (`TY.tabular`, в Canvas нельзя включить tnum, без этого цифры дрожат).
- **Блик**: светлая полоса под наклоном −20°, шириной 110–140px проходит за 0.8–0.9 с; на оффскрин-слое текста — `source-atop` (подсвечивается только текст), на карточках — `lighter`; для трёх карточек прогресс считается по их экранным позициям = один и тот же блик.

## ④ Переходы (5 основных)

1. **Размытый толчок (blurPush)**: старая картинка уменьшается до 0.92 + размытие 24px + затухание, новая из 1.06 с размытием приходит к чёткому 1.0, 0.55 с, `ease`. **Снизу сначала подкладывается сильно размытая старая картинка, увеличенная до 1.08**, — только тогда по краям уменьшенной картинки не видны чёрные поля. Здесь план 1→2.
2. **Раскрытие общего элемента (expandRect)**: (новая картинка с первого же кадра **непрозрачно** вложена в карточку — карточка полупрозрачная, при любом наплыве будут видны наложенные друг на друга старый и новый текст) выбранная карточка (сначала увеличивается до 1.06, боковые отступают и темнеют до 45%) раскрывается из своего экранного прямоугольника на весь экран, скругление 38→0, пружина d=0.55 bounce 0; новая картинка с самого начала масштабирована под размер карточки и вложена в неё. **Выбранная карточка перестаёт парить перед раскрытием**, чтобы переход стартовал от стабильного прямоугольника. Здесь план 2→3.
3. **Монтаж по совпадению (match cut)**: в соседних планах один и тот же объект в одной и той же позиции (название продукта → позиция заголовка карточки).
4. **Вытеснение маской / склейка бликом**: пока проходит блик, картинка меняется позади световой полосы.
5. **Преломление вместо наплыва** (Liquid Glass): при исчезновении элемент постепенно меняет силу преломления/размытия, а не просто снижает прозрачность (проявление текста из размытия здесь — та же идея).

## ⑤ Ритм и текст

- **Длительность плана**: в презентационном выступлении один экран обычно 5–8 с (Jobs, iPhone 2007: 9 экранов за 70 секунд ≈ 7.8 с/экран); в быстром монтаже продуктового ролика 1.5–3 с. Здесь 2.6/3.0/2.4 с.
- **Одна вещь на экран**: одно существительное, одно число, одна карточка. После плотного фрагмента дайте один пустой экран, чтобы зритель перевёл дух (counterweight из Presentation Zen).
- **Синхронизация с озвучкой**: текст начинает проявляться за 0.2–0.3 с до того, как прозвучит существительное (само проявление занимает 0.7 с, к моменту произнесения как раз становится чётким); число **встаёт на место**, когда в озвучке произносится значение — начало счёта = момент произнесения числа − длительность счёта; три карточки появляются по очереди под «первое, второе, третье».
- **Текст**: заголовок ≤6 иероглифов или одно название продукта; подзаголовок — одна фраза ≤16 иероглифов; карточка: заголовок из 4 иероглифов + одна строка пояснения + одно крупное число + единица (на кегль меньше, на уровень серее).

## ⑧ 3 самые частые ошибки

1. **За стеклом ничего нет.** Матовое стекло размывает только то, что за ним; «стекло» на однородном тёмном фоне — просто серый прямоугольник. Сначала нарисуйте цветные, неоднородные световые пятна, затем делайте размытую выборку по экранной позиции карточки.
2. **Пружина слишком упругая, движений слишком много.** bounce по умолчанию 0, при появлении максимум 0.15–0.3; >0.4 — сразу дёшево. За раз двигается только одна группа объектов.
3. **У крупного текста не уплотнён трекинг, цвета пятен грязные.** От 64px и выше −0.015～−0.03em; каждое световое пятно занимает свой участок цвета (наложение screen + сильное размытие), не усредняйте несколько цветов линейно в серо-фиолетовую грязь.
