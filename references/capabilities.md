# Опциональный голос: настройка, пропуск и готовые материалы

Эта страница описывает опциональный голос: готовое аудио, системные голоса macOS, клонирование Volcengine. Канал изображений — в [руководстве по работе с изображениями](images.md). Конфигурация хранится в одном общем внешнем файле; никакие сервисы или плагины не устанавливаются.

## Перед использованием

Проверяйте только тогда, когда задаче нужен голос; беззвучная анимация сразу идёт в процесс работы над картинкой. Если пользователь уже дал подходящую звуковую дорожку — используйте её, если только он явно не просит переозвучить. Для задач только со звуком не нужно запускать дизайн анимации или отсмотр.

`S` обозначает каталог skill, фактически прочитанный в этот раз, а не фиксированный каталог на машине автора или каталог конкретного агента. Claude Code, Codex, Kimi вызывают одинаковый CLI и не зависят от собственных хуков.

```sh
python "$S/scripts/capabilities.py" status --explain
# --project добавляйте только когда нужно прочитать предпочтения доверенного проекта
python "$S/scripts/capabilities.py" status --project <项目> --explain
```

(`<项目>` — проект.)

Проверка читает только конфигурацию этого инструмента, указанный источник учётных данных выбранного адаптера и необходимые локальные зависимости, без проверки по сети. `configured_unverified` означает, что условия для вызова есть, но нельзя утверждать, что аккаунт или качество звука проверены; выбирать способ озвучки нужно только при `needs_configuration`; `prompt:false` означает, что пользователь ранее выбрал ручную настройку — не спрашивайте снова по своей инициативе. Успех фактического запроса подтверждается результатом и квитанцией.

При первом отсутствии конфигурации спрашивайте только о том единственном пункте, который нужен сейчас: использовать запись, системный голос, собственный клон или пропустить. Если пользователь уже указал вариант — выполняйте его выбор; для новых облачных вызовов/платных операций/обучения используйте имеющуюся авторизацию на этот раз, а если её нет — сообщите, чего не хватает. Не просите пользователя вставлять Key в чат.

## Область сохранения и пропуск

Обычный выбор действует только на этот раз; как пользовательское значение по умолчанию он сохраняется лишь когда пользователь говорит «впредь/по умолчанию/запомни». Обычная конфигурация находится вне каталога установки: в macOS/Linux — `$XDG_CONFIG_HOME/huashu/media.json` (если не задано — `~/.config/huashu/media.json`), в Windows — `%APPDATA%/huashu/media.json`. `HUASHU_CONFIG_HOME` может переопределить каталог; `--config` заменяет пользовательский файл по умолчанию.

Агент, собрав выбор, формирует нечувствительный JSON и передаёт его скрипту для записи; скрипт не блокируется в ожидании интерактивного ввода из stdin.

```sh
# Пример JSON: {"preferences":{"voice":{"mode":"system"}}}
python "$S/scripts/capabilities.py" configure --scope user --input <选择.json>
python "$S/scripts/capabilities.py" skip --scope task  # без записи на диск, пропустить на этот раз
python "$S/scripts/capabilities.py" skip --scope user  # впредь включать вручную, не спрашивать повторно
python "$S/scripts/capabilities.py" reset --field preferences.voice
python "$S/scripts/capabilities.py" reset --field onboarding.voice
```

(`<选择.json>` — файл с выбором.)

«Пропустить на этот раз» записывается в состояние текущей задачи — нельзя на следующем же действии снова открывать опрос. Отсутствие ответа — не согласие, и configure при этом не выполняется. Если в пакетной обработке не хватает обязательной конфигурации, возвращается ненулевой код выхода с причиной; беззвучное превью можно сдать, только если пользователь согласен на базовое превью, и называть его полноценным готовым роликом с озвучкой нельзя.

Порядок предпочтений: параметры этого запуска → предпочтения проекта → предпочтения пользователя → общие значения по умолчанию. Проектный `<项目>/.huashu/media.json` принимает только ограниченный набор предпочтений и политику `deny`; в нём нельзя хранить учётные данные, личные привязки тембров или выдавать разрешения. `status --explain` указывает источник каждого поля; запись идёт под межпроцессной блокировкой, `--expected-revision` защищает от того, чтобы целиковое изменение на основе старой конфигурации перезаписало новую.

## Три пути получения голоса

```sh
# 1. Повторно использовать готовое аудио: сохраняется побайтно, генерируются метаданные; если копировать не нужно, можно сослаться на исходную дорожку напрямую
python "$S/scripts/capabilities.py" use-audio --audio 原录音.wav --out <项目>/音频/口播.wav
# 2. Системный голос: только macOS, фиксированно WAV 48kHz; для китайского по умолчанию выбирается из установленных тембров путунхуа
python "$S/scripts/capabilities.py" say "Исходный текст для озвучки" --mode system --out <项目>/音频/口播.wav
# 3. Настроенный и авторизованный клон Volcengine
python "$S/scripts/capabilities.py" say "Исходный текст для озвучки" --mode clone --out <项目>/音频/口播.wav
# Старый способ вызова остаётся совместимым и использует ту же конфигурацию
python "$S/scripts/koubo.py" say "Утверждённая реплика для дозаписи" --out <项目>/音频/补配.wav \
  --fit 3.5 --match 原音轨.wav --match-ss 10 --match-t 3.5
```

(`原录音.wav` — исходная запись, `音频/口播.wav` — аудио/озвучка, `补配.wav` — дозапись, `原音轨.wav` — исходная дорожка.)

Существующий выходной файл не перезаписывается. После успеха рядом пишется `音频文件.json` (sidecar аудиофайла) с длительностью, частотой дискретизации, SHA и источником; для клона записывается запрошенная модель — нельзя выдавать её за фактическую модель, о которой сообщил сервер. Сырой PCM сначала проходит приёмку как аудио в контейнере, затем экспортируется в s16le, частота дискретизации и моно-формат записываются в sidecar. Системные тембры не поддерживают параметры модели и скорости речи от Volcengine.

Общее значение по умолчанию — «способ озвучки не выбран», а не тембр автора. Рекомендуемые параметры Volcengine по умолчанию — expressive, режим восстановления, скорость речи 0; пользователь может изменить их в `provider_options.volcengine`. Личная конфигурация может хранить другие скорость и тембр. Полный список полей — в `schemas/media.schema.json`, не угадывайте поля.

Уже существующие на платформе тембры переобучать не нужно:

```sh
python "$S/scripts/capabilities.py" bind --name narrator --speaker-id S_xxx --default
```

bind только регистрирует локальный псевдоним: не обращается к платформе, не меняет исходный `~/.koubo/voices.json` и не включает облачные вызовы автоматически. `--default` меняет только ссылку по умолчанию; способ генерации всё равно нужно выбрать clone.

## Настройка и авторизация Volcengine

Учётные данные читаются из переменных окружения процесса; можно также указать существующий файл в личном `bindings.volcengine.env_file` или временно задать его через `KOUBO_ENV`. Переменные окружения имеют приоритет; .env в текущем каталоге, домашнем каталоге или рабочей области автора автоматически не перебираются. В конфигурации хранятся имена переменных/ссылки на файлы, но не значения Key.

Для включения облачного клонирования нужны: `preferences.voice.mode=clone`, разрешимый тембр и `policy.cloud`, `policy.paid_api` со значением allow — либо явная авторизация пользователя на этот раз. `--allow-cloud`, `--allow-paid-api` служат только для выражения уже полученной авторизации на этот раз, а не способом обойти правила, и не перекрывают deny. Если пользователь меняет собственный запрет — сначала явно измените соответствующую конфигурацию; ограничения хоста/организации продолжают действовать. Проект может только ужесточать, но не авторизовать.

Сетевой прокси управляется личным `bindings.volcengine.trust_env`, общее значение по умолчанию следует окружению; не навязывайте всем установщикам опыт сбоев прокси на какой-то конкретной машине. Базовой конфигурации/готовому аудио нужна только стандартная библиотека Python; для приёмки аудио нужен ffprobe, для системного голоса и подгонки — ffmpeg, для Volcengine дополнительно requests. Если зависимостей не хватает — сообщите, не устанавливайте автоматически.

Обучение — отдельная операция, требующая явного указания слота тембра и авторизации на это обучение; `--force` пропускает только проверку низкого уровня сигнала, но не авторизацию. Результат обучения становится значением по умолчанию в реестре только при передаче `--default`.

```sh
python "$S/scripts/koubo.py" train --audio 自己的录音.wav --speaker S_xxx --name 我的声音 \
  --allow-cloud --allow-paid-api --allow-voice-training
```

(`自己的录音.wav` — собственная запись, `我的声音` — «мой голос», имя тембра.)

Обучение изменяет удалённый тембр. Флаги авторизации из примера можно использовать только после фактического согласия пользователя; не считайте это обычным подготовительным шагом перед синтезом.

## Приёмка и сбои

Подгонка сохраняет прежнюю грубую настройку + atempo, не более 3 генераций; каждая может тарифицироваться. Если итоговое расхождение больше ±0,05 секунды, возвращается сбой и сохраняется кандидат `.unfitted` — нельзя выдавать длительность за соответствующую. Синтез обязан получить от сервера финальное сообщение об успехе; почти пустой, беззвучный или ошибочный ответ не фиксируется как итоговый результат. Сетевой таймаут мог означать, что заказ уже принят, — помечайте результат как неопределённый и не повторяйте запрос вслепую.

Для финального ролика всё равно нужны пословная сверка и прослушивание имён собственных; CLI не выбирает автоматически из трёх кандидатов на слух и не делает ASR. При дозаписи проверяйте стыки, субтитры и таймлайн картинки; если уже используется video-pipeline — подключайтесь к его процессу вклейки и субтитров, самостоятельные пользователи могут использовать свой монтажный проект.
