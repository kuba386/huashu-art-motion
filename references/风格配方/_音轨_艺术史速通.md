# Метод звуковой дорожки · синтезированная кодом музыка для спидран-ролика (метод разбора + оригинальный пример)

Эта страница — метод, выкристаллизовавшийся из одного разбора: референс — 15-секундный «Art History Speedrun» пользователя X Tak (@cherry_mx_reds), музыка к которому сама синтезирована кодом. Здесь сохранено только **как разбирать, как писать, как сводить**, без нотной транскрипции оригинала.

Сопутствующий скрипт: `scripts/audio/synth_艺术史速通.py`. Партитура — **оригинальный пример** (ре минор, гармония Dm–B♭–F–C), структура частей совпадает с `scripts/engine/eras.js` для изображения; библиотеку инструментов и цепочку сведения можно переиспользовать напрямую, достаточно подставить свою партитуру.

---

## 0. Вывод в одной фразе

Музыка для спидран-роликов может быть **процедурной аранжировкой на строгой BPM-сетке**: 17 эпох расставлены по «числу восьмых» (6,4,4,4,4,4,3,3,3,3,2,2,2,1,1,1,9), чем дальше, тем короче каждая часть; ощущение ускорения создаётся «укорочением частей», сам темп не меняется. В каждой части меняется набор характерных для эпохи инструментов, один трёхнотный мотив транспонируется вслед за аккордами и проходит через весь ролик. Когда музыка останавливается на сетке, следует серия мультяшных звуковых эффектов (дзинь, падение со свистком-слайдом, звон разбитой посуды, мяуканье, финальный щипок), которые доводят финальный гэг.

## 1. Как разобрать референсную музыку

| Что измеряем | Метод | Точность/достоверность |
|---|---|---|
| Темп и сетка | Спектральный поток в стиле superflux по STFT (hop 2.5ms), пики берутся как атаки, затем МНК-подгонка `t = t0 + n·E` (всего 28 атак) | E = 0.23431s (восьмая) → **128.04 BPM**, нулевая точка сетки t0 = 0.028s. Все остатки в пределах ±4ms, живой исполнитель так не может — можно утверждать, что это программное расписание |
| Границы эпох | Три независимых подтверждения: ① положение на сетке; ② пики кривой новизны MFCC (расстояние между средними за 0.2s до и после); ③ пики покадровой разности видео | Отклонение аудиограниц (сетка) от пиков MFCC ≤20ms. Переходы в изображении отстают от аудио на 0–0.2s (в изображении используются переходы-вытеснения/трансформации длительностью 0.1–0.2s) |
| Высота тона | ① полифоническая транскрипция Spotify basic-pitch (ONNX, временное окружение Python 3.11); ② на сетке шестнадцатых берутся пики FFT 85ms, прирост >6dB до/после атаки считается новой нотой; ③ ручная сверка по собственной CQT-карте энергии по полутонам | Основная мелодия — высокая достоверность (два метода совпадают). Внутренние голоса гармонии, детали частей укиё-э и Ван Гога — средняя достоверность |
| Тембр | Для каждой мелодической ноты берутся амплитуды гармоник через 20–220ms после атаки (H1–H8, узкая полоса ±1.5%), затем измеряются время атаки и затухание узкополосной огибающей (+50/100/200ms относительно пика) | Полифония подмешивает другие голоса, соотношения гармоник можно считать только тенденцией |
| Ударные | По каждой шестнадцатой измеряются скачки энергии >6kHz (шумовые) и <150Hz (барабанные) | Высокая |
| Звуковые эффекты | На 13–15s отслеживаются траектории частоты по пикам FFT с шагом 20ms, события выравниваются по 2.1-секундному листу контактов изображения (один кадр на 0.1s) | Высокая |
| Громкость | ffmpeg ebur128; по частям — среднеквадратичное с K-взвешиванием BS.1770 без гейтинга | В целом **-14.3 LUFS, LRA 0.9 LU, true peak -2.4 dBTP** (часто встречающиеся «в среднем -16.6dB» — это среднее RMS, другая методика) |
| «Прослушивание» омнимодальной моделью | Омнимодальная модель прослушивает весь ролик целиком, вопросы задаются с позиции композитора | Только как кандидаты, каждый пункт перепроверяется, см. раздел 4 |

---


Ещё два наблюдения: тембр надёжнее всего определять по «амплитудам гармоник через 20–220ms после атаки + затуханию узкополосной огибающей»; чтобы понять, «синтезировано ли кодом», смотрите на три вещи — укладываются ли временные остатки в ±5ms, состоят ли все тембры из хрестоматийных компонентов вроде синуса/меандра/пилы/экспоненциального затухания, есть ли в тихих местах шумовой фон записи.

## 3. Финальные звуковые эффекты (по схеме «стоп — подвес — удар — реакция — финал»)

| Событие | Способ синтеза (функция в скрипте) |
|---|---|
| Музыка останавливается | Бас быстро затухает примерно за 150ms, без жёсткого обрыва |
| Лапа задевает чашку — «дзинь» | Несколько негармонических звонов 5–7kHz + немного 1.5kHz (`tink`), одновременно высокочастотный свист-«вжух» (`swipe`) |
| Чашка падает | Чистый синус, экспоненциальный спуск примерно 1550→325Hz, 0.35s (`slide_whistle`) |
| Разбивается об пол | Глухой удар около 80Hz + широкополосный шум (центроид 5–7kHz, затухание около 0.45s) + негармонические обертоны керамики + несколько мелких ударов осколков (`crash`) |
| Мяуканье | Гармонический синтез с линейной ломаной высотой тона (вверх, потом вниз) + две форманты, самое громкое место ролика (`meow`) |
| Появление подписи | Два лёгких «поп» на ~90Hz с небольшим ярким призвуком (`end_thump`) |
| Финал | Басовый щипок на тонике |

Все моменты времени выравниваются по событиям изображения через лист контактов (один кадр на 0.1s).

## 4. Сведение (вторая половина скрипта, можно использовать как есть)

1. Ревербератор маленького помещения 0.5s, предзадержка 12ms, мокрый сигнал 9%
2. Тёплая НЧ-подложка по частям: по корню аккорда части (`BED_ROOT`) кладётся «треугольник + синус октавой ниже, ФНЧ 250Hz», уровень автоматически вычисляется из относительной величины «НЧ-пол относительно громкости части», частям, где низа и так хватает, ничего не добавляется
3. Динамический эквалайзер 2–6kHz по частям (`MID_ORIG`)
4. Добавление «воздушного» шума >6kHz по частям (`HF_ORIG`)
5. Выравнивание громкости с K-взвешиванием по частям к `target`, 4 итерации, сглаживание усиления 10ms против «молниевого» треска (zipper noise)
6. Опционально: крутой ФНЧ на 15.8kHz для имитации стримингового AAC
7. Общее выравнивание LUFS, затем лимитер пиков с упреждением

Если есть референс, в `target / MID_ORIG / HF_ORIG / LOW_FLOOR_ORIG` подставляются значения, измеренные по частям референса (методом из раздела 1); без референса достаточно «единых относительных значений» из примера.

Опыт смягчения атаки: жёсткая атака 2ms в модели щипка звучит слишком «точечно»; если перейти на линейную атаку 10ms, атаку высших гармоник сделать позже (×1.6 на каждую следующую гармонику, максимум 35ms), шум атаки уменьшить вдвое и добавить ФНЧ 7kHz, звучание становится гораздо более связным.

Результат примера: 48k стерео, 15.06s, -14.0 LUFS, true peak -1.5 dBTP.

```
uv run --with numpy --with scipy --with soundfile python scripts/audio/synth_艺术史速通.py
```

## 5. Переиспользуемые закономерности: синтезированная кодом музыка для любой анимации

Это можно копировать напрямую.

1. **Сначала задайте BPM-сетку и выравнивайте по ней всё**. 128 BPM (восьмая 0.234s) подходит для ритма «спидран, монтаж»; точки монтажа, атаки музыки, моменты звуковых эффектов — всё берётся как `t0 + n·E`. Плюс в том, что как бы ни резалось изображение, музыка не будет звучать хаотично. Временные остатки в референсе всего ±4ms, и эта «машинная точность» сама по себе часть стиля.
2. **Ускоряйте за счёт «убывающего числа восьмых в части», а не повышения темпа**. В этом ролике 6 → 4×5 → 3×4 → 2×3 → 1×3, а последняя часть снова длинная (9) — даёт зрителю передохнуть и оставляет место для гэга. Темп не меняется, но на слух всё стремительнее; к тому же каждая часть попадает в сетку и естественно синхронизирована со склейками изображения. Как делать: выпишите длительности частей изображения, округлите до восьмых, затем подкорректируйте всё вместе, чтобы убывание стало регулярным.
3. **Один трёхнотный мотив, меняющий инструменты и транспонируемый вслед за аккордами**. Выберите короткую ритмически яркую клетку (в партитуре-примере ♪♪♩ — «поступенный подъём, затем скачок вниз»), в каждой сцене она проигрывается характерным для эпохи или стиля инструментом, высота следует за аккордом части. Для гармонического каркаса хватит цикла из четырёх аккордов (в примере Dm–B♭–F–C); в частях, где нужно «выбивающееся» ощущение (экзотика, авангард), меняйте только лад или добавляйте тритон, ритм и сетку не трогайте. В начале мотив можно сперва утвердить в обращении или увеличении (в примере в части «Пещеры» — нисходящие четверти с точкой).
4. **Без кроссфейдов между частями**. Новая часть начинается с жёсткой атаки на сетке, ноты предыдущей части сохраняют свой естественный хвост (щипок 30–300ms, выдержанный звук — release около 150ms), можно протянуть басовую педаль через границу, чтобы «сшить» две части. Так каждая смена сцены даёт отчётливый «щелчок», но без разрыва. Добавлять «вжух»-переход к каждой части не нужно (в референсе нет ни одного).
5. **Финальные эффекты проектируются по схеме «стоп — подвес — удар — реакция — финал»**:
   - Стоп: музыка останавливается на сетке, быстрое затухание около 150ms, без жёсткого обрыва
   - Подвес: маленький «дзинь» как затравка, затем свисток-слайд (чистый синус, экспоненциальная развёртка по частоте, около 0.35s, больше 2 октав)
   - Удар: глухой удар + широкополосный шум + негармонические обертоны + несколько мелких ударов осколков, полное затухание около 0.45s
   - Реакция: голос персонажа, например «мяу» с линейной ломаной высотой тона, примерно через 0.5s после удара, самое громкое место ролика
   - Финал: один-два лёгких «поп» под подпись, последним — басовый щипок на тонике или доминанте
   Всё выравнивается по моментам событий через лист контактов изображения (один кадр на 0.1s).
6. **Метод выравнивания громкости**:
   1. Сначала измерьте общие значения референса (ffmpeg ebur128: интегральный LUFS, LRA, true peak)
   2. Затем по частям измерьте громкость с K-взвешиванием, а также разницы 2–6kHz, >6kHz, НЧ-пола 40–220Hz относительно громкости части
   3. После синтеза по порядку: тёплая НЧ-подложка по частям → динамический EQ средних-высоких по частям → «воздушный» шум по частям → итеративное выравнивание громкости по частям (3–4 раза, сглаживание усиления 10ms против zipper noise)
   4. Если референс в AAC, добавьте ФНЧ на 16kHz
   5. В конце — общее выравнивание LUFS и лимитер пиков с упреждением
   Везде используются разницы «относительно громкости части», а не абсолютные значения — так при смене материала или общей громкости ничего не нужно перекалибровывать.
7. **Как превратить synth.py в универсальный шаблон** (структура не меняется, заменяются только четыре блока данных):
   - `T0, E`: нулевая точка сетки и длительность восьмой (BPM → `E = 60 / BPM / 2`)
   - `edges / target / MID_ORIG / HF_ORIG / LOW_FLOOR_ORIG / BED_ROOT`: границы частей и референсные значения по частям; без референса в `target` достаточно одного значения (например -14), остальные три — «без добавки»
   - Блоки партитуры `era(n0, items)`: по одной строке-списку на часть, элементы — `(относительная позиция в восьмых, функция инструмента, усиление, панорама)`. Библиотеку функций инструментов (семейство щипковых `pluck`, семейство выдержанных `additive`, семейство барабанов `kick / clap / hat / taiko`, семейство синтезаторов `chip / supersaw`) можно переиспользовать напрямую; для нового стиля обычно достаточно настроить таблицу гармоник и параметры затухания `pluck`
   - Блок эффектов: по времени событий вызываются `tink / slide_whistle / crash / meow / end_thump`, параметры (частота, длительность) измеряются по референсу или задаются самостоятельно по шаблону из пункта 5
   Цепочка сведения во второй половине (подложка → EQ → воздух → итерации громкости → ФНЧ → лимитер) сохраняется как есть.
8. **Порядок анализа**:
   1. Подгонка сетки по потоку атак — сначала получить BPM и t0
   2. Покадровое (по ячейкам) обнаружение новых нот через FFT на сетке шестнадцатых, затем перекрёстная проверка полифонической транскрипцией basic-pitch
   3. Тембр — по узкополосным соотношениям гармоник и огибающей
   4. Ударные — по скачкам энергии в ВЧ и НЧ
   5. Омнимодальная модель — только как кандидаты, каждый пункт перепроверяется. На практике она надёжна в определении инструментов, но ошиблась в темпе (сказала 120, измерено 128), в числе нот мотива, в «вжух»-переходах и во времени звуковых эффектов
