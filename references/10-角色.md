# 10 · Персонажи: человека генерирует AI покадрово, код отвечает за композитинг

Когда дело касается генерации изображений или картинок персонажей, сначала по [руководству по работе с изображениями](images.md) выберите доступный сейчас инструмент или импортируйте готовые материалы; личные материалы персонажей и выбор платформы не являются настройками по умолчанию для всех пользователей.

## Выбор способа реализации персонажа

Один и тот же персонаж может быть реализован тремя способами (сравнение A и B бок о бок — в `assets/角色/花叔形象_对比.jpg` (сравнение образа Хуашу); результат C — в демо-роликах Kurzgesagt и доски-скетча):
- **A Рисовать кодом**: подходит для геометрических персонажей и болванок для движения; сложные лица передаёт плохо.
- **B Вставлять готовую библиотеку кадров**: легко сохранить единообразие персонажа, но нужно согласовать стиль изображения библиотеки кадров и сцены.
- **C Сгенерировать кадры действий в стиле ролика и скомпоновать**: идентичность держится за счёт референса, после кеинга по зелёному фону движение и материал контролирует код.

Для реальных людей и антропоморфных персонажей предпочтительны B или C, геометрических персонажей можно по-прежнему рисовать кодом. В карточках стилей сохранены известные слабые места для каждого типа персонажей.

## B: вставка готовой библиотеки кадров

- Библиотека кадров: ваши собственные утверждённые кадры персонажа (например, помахать рукой, тащить и т. п. — по 8 прозрачных PNG на действие; кадры для общих действий готовьте сами; кадры персонажа для трёх сегментов, приложенные к демо ролика-свитка, лежат в `scripts/engine/demos/long_scroll/frames/`).
- При запуске движка загружаются как графические ресурсы; при рендере кадр меняется по `floor(t*9)%8` — ограниченная анимация без промежуточных фаз.
- Точка привязки — центр подошвы; `face=-1` — отражение по горизонтали.
- Наложите на кадры материал того ролика, в который они вставлены (у Vox — белый край вырезанной бумаги и тень; в стилях с мазками можно поверх кадра пройти ещё слоем мелких мазков через source-atop).

## C: генерация версии в стиле ролика

1. **Генерация изображений**: используйте модель с поддержкой референсов вроде gpt-image (как писать prompt — см. [huashu-gpt-image](https://github.com/alchaincyf/huashu-gpt-image)), пакеты запускайте последовательно. ref = концепт-лист персонажа в трёх ракурсах или мастер-кадр готовой библиотеки; в prompt ясно опишите:
   - **пластический язык** стиля (а не просто «в стиле XX»): Kurzgesagt — плоские цветовые пятна без обводки, тень — тот же тон на ступень темнее; Vox — чёрно-белые растровые газетные фото + белый край вырезанной бумаги; доска — чёрный маркерный линейный рисунок + оранжевая штриховка; Моне — короткие мазки, световые пятна…
   - **согласование позы и мизансцены камеры** («повернулся боком вправо, протягивает руку и указывает вправо»); для движения — несколько кадров одним sprite (4×2, восемь кадров; число кадров в начале, «один и тот же персонаж» для фиксации единообразия, давать только ключевые позы, чтобы модель дорисовала промежуточные, «в каждом кадре персонаж стоит по центру внизу ячейки, размер одинаковый»).
   - Зелёный фон `#00B140` (белая шляпа и белая футболка не позволяют использовать белый фон).
   - Фиксированные правила (на примере образа Хуашу): **чисто белая** панама (модель любит рисовать её светло-серой, это надо прописать жёстко), круглые чёрные очки, белая футболка, шорты цвета хаки, белые сабо-кроксы, чёрные часы на левом запястье, большая голова и маленькое тело.
2. **Проверка подлинности**: основание — реальные записи вызовов инструмента, связь входа/выхода и ручная визуальная проверка; метаданные PNG не доказывают, какой моделью сгенерировано изображение. Подключение материалов — см. [руководство по работе с изображениями](images.md).
3. **Кеинг и нарезка кадров**: `scripts/key_split.py` (удаление зелёных отсветов, нарезка поз по столбцам; для линейного рисунка на доске — `--white`: только обрезка без кеинга, в кадр вставляется через multiply); если нужно сохранить координаты исходного изображения — `scripts/key_green.py`.
4. **Композитинг**: код решает только положение, размер, направление, момент смены кадра и материал; камешки, круги на воде, реквизит и другие интерактивные объекты по-прежнему рисуются кодом и выравниваются по положению руки.

## Когда всё ещё рисовать кодом

Геометрических персонажей (кубики, терминалы, роботы, птички, коты), силуэты, минималистичных человечков-символов (человечки Харинга, палочные человечки на доске) можно рисовать кодом. Скелеты девушки/кота в `lib/rig.js` и `rig_huashu.js` сохранены: для референса движения (где рука, где нога — якорные точки для AI-кадров), для превиза болванками и для геометрических стилей.
