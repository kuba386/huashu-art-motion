# 08 · Регламент для авторов стилей (общая версия — для тех, кто пишет scene, и для агентов, которым поручается работа)

> Заменяет ранний `时代作者规范.md` (регламент для авторов эпох), жёстко привязанный к проекту-реплике. Поручая агенту нарисовать стиль, дайте ему путь к этой странице и добавьте конкретику из раздела «этот проект».

## Интерфейс

Один стилевой сегмент = `scenes/<id>.js`:

```js
SCENES['<id>'] = { draw(c, lt, t) { /* заполнить 1920×1080 целиком */ }, init(IMG) { /* необязательно: однократный предрасчёт */ } };
```

- `c` — целевой 2D context; `lt` — локальное время сегмента (секунды, отсчёт от начала перехода в этот сегмент); `t` — время всего ролика.
- Таблица сегментов `eras.js`: `{ id, eighths или dur, transition: { type, dur }, counter: {...} }`. Длина ролика вычисляется по таблице сегментов автоматически.
- Переходы `transitions.js`: `TRANSITIONS.<name> = (c, A旧, B新, p, o) => {}` (A — старый, B — новый).
- Нет файла сцены, синтаксическая ошибка, сцена не зарегистрирована → движок отказывается запускаться, render/qa сразу падают с ошибкой. Не судите об успехе по принципу «вроде отрендерилось».

## Сначала прочитать (по порядку)

1. `references/02-机制.md` (пять слоёв механизма), `04-纯代码绘制.md` (конвейер, шпаргалка по рендерерам, грабли), `07-正面经验.md` (положительный опыт).
2. `references/风格配方/INDEX.md` (указатель карточек стилей): найдите самый близкий стиль как отправную точку и прочитайте его карточку.

## Две отправные точки

**Есть референсный ролик**: сначала запустите `scripts/analyze/breakdown.py`, получите референсные кадры (`ref/segNN.png`), тепловую карту движения, контактный лист переходов, и разбирайте по № 01. Референсные кадры определяют композицию, мотивы и палитру, тепловая карта — «что в картине движется».

**Референсного ролика нет** (бывает чаще):
1. Выпишите 3–5 самых узнаваемых формальных элементов стиля (материал, манера мазка, палитра, мотивы, следы техники). Ищите первоисточники (изображения оригиналов, искусствоведческие описания), не полагайтесь на впечатление.
2. Каждому элементу подберите «способ двигаться» — как он двигался бы в мире этой картины (вода дрожит, бумага колышется, золото мерцает, печатная форма сдвигается, плёнка дёргается).
3. Разберитесь, как такая живопись делается в реальности (кисть, резьба, печать, аппликация, инкрустация, распыление, рендер), и запишите этот физический процесс как рендерер.
4. Сначала один кадр: сравните склейку статичных кадров с оригиналом, и только когда стиль узнаётся с первого взгляда — оживляйте.

## Жёсткие требования

1. **Каркас сцены**: расставляйте по координатам композиции, заданным проектом (одинаковым во всех сегментах — от этого зависят переходы и ощущение «один и тот же персонаж путешествует»).
2. **Персонаж**: используйте скелет `RIG` и общую хореографию — меняется манера рисования, а не позиция и движения. **Персонаж тоже должен пройти материальную обработку стиля** (мазки, зерно, бумажная фактура через multiply, расплыв туши по краю, растр, сдвиг цветоделения…), иначе он выглядит как наклеенный клипарт — это самый частый недостаток среди 36 стилей. Если нужен линейный рисунок — `drawGirl/drawCat` с `mode:'line'` (внутри уже используется visibleLines, линии не пройдут насквозь).
3. **Картина должна жить**: главное действие + 2–4 маленьких цикла мотивов, заметных в окне показа. В роликах-спидранах/путешествиях действия персонажа берут время всего ролика (`PAINT.cupCycle(t)` и т. п.) и не сбрасываются при смене сегмента.
4. **Плавность**: не перетасовывайте весь экран сменой сида с низкой частотой (это читается как мерцание); «кипение» — только для линейного рисунка или зон мотивов. Намеренная «пошаговая частота» (rubber hose 12fps, театр теней 10fps) — через `stepTime`, это стиль, а не подтормаживание. Период взятия по модулю у прокручиваемого узора равен реальному периоду узора.
5. **Детерминизм**: вся случайность — по сиду; два рендера одного t совпадают попиксельно.
6. **Производительность**: статические части — `PAINT.cached`; внеэкранные буферы с чтением пикселей — `willReadFrequently`, каждый кадр `g.reset()`; цель — ≤150 мс на кадр (qa меряет реальное время с GPU flush).
7. **Текст**: текст в стиле предпочтительно рисуйте путями в материале стиля; если используете шрифт — сначала проверьте наличие глифов через `U.assertGlyphs` (отсутствующие символы молча откатываются на системный шрифт).
8. **Состаривание не на персонаже**: отслоения, пятна, царапины — только на фоне; для зоны персонажа задайте охранную область (пятна отслоения Дуньхуана на спине читались как «дыры в одежде»).

## Самопроверка и сдача

```sh
uv run --with playwright python <工程>/render.py --solo <id> --stills 0.4,0.6,0.8,1.0 --out <渲染>/<id>   # статичные кадры
uv run <skill>/scripts/qa.py --project <工程> --ids <id>                                                # цифры
```

(`<工程>` — проект, `<渲染>` — папка рендеров.)

Каждый сегмент — минимум 3 итерации: сравнить статичные кадры с оригиналом/референсной склейкой → qa: движение/пары статичных кадров/скачки/время/детерминизм → исправить. Четыре вопроса: ① Узнаётся ли стиль с первого взгляда? ② Персонаж правильный и сливается ли с фоном? ③ Видно ли в окне показа, что картина движется, и при этом нет мерцания и рывков? ④ Нет ли ляпов (перекрытия, оборванные линии, сдвиги, пустоты, наложение текста)?

Сдача: `scenes/<id>.js` + карточка рецепта (по формату `风格配方/`: конвейер, ключевые параметры и значения цветов, как сделана анимация мотивов, фирменный переход, производительность, грабли, что ещё можно улучшить) — конкретно, с цифрами. **Перед сдачей многосегментного ролика поручите агенту, который не участвовал в производстве, отсмотреть только готовый ролик.**

## Жёсткое правило «трёх направлений» без присмотра

Если Хуашу на месте: новое направление стиля и трактовку персонажа сначала покажите в трёх вариантах на одном кадре — пусть выберет.
Если спросить некого (автотесты, ночная пакетная работа): выполняйте направление, указанное в задании, а в описании при сдаче перечислите «два других направления, которые можно было предложить», по одной фразе на каждое, — пусть выберет, когда вернётся.
