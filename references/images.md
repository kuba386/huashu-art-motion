# Опциональные изображения: готовые материалы и генерация текущим агентом

Подключение изображений делится на две части: агент наблюдает текущие инструменты и вызывает их в рамках авторизации пользователя; скрипт разбирает выбор, проверяет результат и сохраняет его в проект. Скрипт не имитирует инструменты хоста, не заимствует состояние входа других агентов и не переключает API изображений автоматически.

## Сначала задача, потом конфигурация

Готовые изображения сразу импортируйте через `use-image`. Анимация чистым кодом без изображений эту страницу пропускает. Для новой генерации сначала прочитайте явные предпочтения в правилах, загруженных в этот раз, затем конфигурацию этого инструмента; если пользователь уже попросил сгенерировать — выполняйте с фактическим инструментом и имеющейся авторизацией, не переспрашивая насильно ради заполнения конфигурации.

```sh
# S — каталог skill, фактически загруженный в этот раз
python "$S/scripts/capabilities.py" image-status
python "$S/scripts/capabilities.py" use-image --file 原图.png --out <项目>/配图/素材.png
```

(`原图.png` — исходное изображение, `<项目>/配图/素材.png` — проект/иллюстрации/материал.)

`preferences.image.mode` поддерживает `unconfigured/off/existing/generate`, provider — точный ID текущего инструмента или auto. `off` — предпочтение «по умолчанию не генерировать», явная просьба сгенерировать в этот раз его перекрывает; `policy.image_generation=deny` — запрет, временные флаги авторизации его не перекрывают. Явный «запрет» пользователя сохраняйте как policy, а не только как mode.

При первом отсутствии конфигурации спрашивайте только: готовые материалы / разрешить генерацию текущим инструментом / пропустить. `skip --capability image --scope task` на диск не пишется, `--scope user` означает долгосрочное ручное включение. Если пользователь выбрал только «на этот раз», не сохраняйте это как долгосрочное значение по умолчанию. Существующая голосовая конфигурация после обновления продолжает действовать, новая возможность работы с изображениями остаётся невыбранной и автоматически не разрешается.

## Снимок текущих инструментов

Агент читает имена и schema из списка инструментов, уже открытых в текущей сессии (или через официальный поиск инструментов хоста), подтверждает поддерживаемые операции и записывает снимок в рамках задачи. Делать вывод по сканированию Key, установленным skill или имени агента нельзя. Если инструментов нет — пишите `tools: []`.

```json
{
  "host": "codex",
  "session_id": "уникальный идентификатор этой задачи",
  "observed_at": 0,
  "tools": [{
    "id": "ID фактического текущего инструмента",
    "kind": "host",
    "operations": ["generate", "edit"],
    "reference_images": true,
    "transparent_background": true,
    "cost": "subscription",
    "network": "cloud"
  }]
}
```

Пример — не декларация возможностей: в `observed_at` нужно вписать текущее Unix-время, характеристики и ID инструмента должны браться из фактической schema этого раза; снимок действителен 15 минут. host может быть codex, claude-code, kimi, other; kind — host или mcp. Тип тарификации — subscription/paid_api/unknown/none; сеть — cloud/local. Подписка не означает отсутствие лимитов; если тарификация неясна — ставьте unknown, нельзя ставить none.

Все три хоста работают по этому общему контракту. То, что в какой-то сессии Codex есть image_gen, не значит, что он есть во всех продуктовых поверхностях Codex; Claude Code/Kimi могут использовать подходящий MCP-инструмент для изображений, если он открыт, а если нет — импортируйте готовые изображения или дайте описание материалов, которые нужно подготовить. Нельзя выдумывать у этих двух хостов встроенные инструменты с тем же названием.

## План → выполнение хостом → приёмка

JSON запроса:

```json
{
  "prompt": "описание изображения, подтверждённое пользователем",
  "operation": "generate",
  "references": [],
  "transparent_background": true,
  "min_width": 512,
  "min_height": 512
}
```

Для правки изображения используйте edit и передайте референсные файлы; относительные пути считаются относительно JSON запроса. Скрипт проверяет, что референсы декодируются, и сохраняет hash; последующее их изменение делает старый план недействительным.

```sh
python "$S/scripts/capabilities.py" image-plan --request 需求.json \
  --host-tools 当前工具.json --session 本次标识 --mode generate \
  --allow-image-generation --allow-cloud --out 执行计划.json
```

(`需求.json` — запрос, `当前工具.json` — текущие инструменты, `本次标识` — идентификатор этого раза, `执行计划.json` — план выполнения.)

Флаги авторизации лишь выражают авторизацию на этот раз, уже данную пользователем. Для загрузки референсов в облако дополнительно нужен `--allow-reference-upload`; для явно платного API — `--allow-paid-api`; для неизвестной тарификации — `--allow-unknown-image-cost`. Долгосрочное разрешение можно сохранить в соответствующих полях policy. Проект может задавать только deny и не может выдавать эти права. Запреты обрабатываются первыми; если среди нескольких разрешённых инструментов всё равно нельзя однозначно выбрать — возвращается needs_selection, платформу самовольно не угадываем.

Получив `host_action_required`, агент вызывает инструмент по его настоящей schema; план — это смысловые требования, а не универсальное тело параметров для всех платформ. Квитанция пишется только при успешной генерации:

```json
{
  "status": "success",
  "plan_id": "ID из плана выполнения",
  "session_id": "идентификатор этого раза",
  "tool_id": "ID фактически вызванного инструмента",
  "output_sha256": "SHA256 фактического выходного файла"
}
```

Сохраняйте фактическую запись вызова инструмента как основание. Квитанция — запись вызова, предоставленная агентом, а не подпись платформы; одни лишь метаданные PNG не доказывают, какая модель сгенерировала изображение.

```sh
python "$S/scripts/capabilities.py" accept-image --plan 执行计划.json --receipt 回执.json \
  --host-tools 当前工具.json --session 本次标识 --file 宿主输出.png \
  --out <项目>/配图/正式素材.png --allow-image-generation --allow-cloud
```

(`回执.json` — квитанция, `宿主输出.png` — вывод хоста, `正式素材.png` — финальный материал.)

Приёмка заново сверяет текущую авторизацию, конфигурацию изображений, инструмент, сессию, референсы, hash файла, фактический размер и прозрачные пиксели. План действителен 1 час; если снимок возможностей устарел — сначала обновите его, нельзя править старый план и делать вид, что он ещё действителен. Если уже существует исходный файл или sidecar — перезапись не выполняется; поддерживаются статичные PNG/JPEG/WebP, нужен Pillow, инструмент не устанавливает его автоматически. Содержимое изображения и соответствие референсной идентичности всё равно нужно проверять глазами — hash/размер не заменяют просмотр.

После прохождения файл копируется в проект и рядом пишется JSON с размером, прозрачностью, SHA, ID инструмента, связью с планом и `provenance: agent_reported_tool_call`. Не ссылайтесь на кэш агента как на финальный материал проекта и не заявляйте, что проверено имя модели, которое сервер не вернул.

## Расширение и возврат опыта

Добавляя адаптер API изображений, сначала выберите реального поставщика, затем реализуйте его протоколы аутентификации, запросов, вывода и ошибок и напишите контрактные тесты на успех/сбой. URL, называющий себя OpenAI-compatible, не становится автоматически пригодным бэкендом; в этой версии нет универсального исполнителя API или самоустановщика. Существующие MCP-инструменты относятся к каналу инструментов текущего агента и вызываются по их schema.

2026-10-08: в P2 создан интерфейс выбор → действие хоста → приёмка материала. Перед повторным использованием прочитайте эту страницу и текущее описание инструментов поставщика; при воспроизводимых сбоях добавляйте тест и исправляйте исходную логику, личные вкусы пишите только в личную конфигурацию. Голос и изображения включаются независимо, обновление не расширяет уже выданную авторизацию. Детерминированная приёмка и выводы о визуальном качестве фиксируются раздельно.
