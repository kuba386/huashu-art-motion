# Клонирование голоса Volcengine Doubao 2.0 · детали интерфейса и записи замеров

Исторические записи по интерфейсу — от 2026-09-13, раздел о запросе статуса обновлён 2026-09-18; новым пользователям сначала настроить всё по capabilities.md, ограничения сервиса определяются фактическим ответом на момент вызова. Официальная документация: библиотека «Doubao Speech» (豆包语音) в центре документации Volcengine (LibraryID 6561).

## Аутентификация

Старая консоль (APP ID + Access Token):

```
X-Api-App-Id:      {APPID}
X-Api-Access-Key:  {Access Token}
X-Api-Resource-Id: volc.megatts.voiceclone   # обучение / запрос статуса
                   seed-icl-2.0              # синтез
X-Api-Request-Id:  {uuid}
Content-Type:      application/json
```

Новая консоль использует `X-Api-Key` (берётся в управлении API Key). Официально сказано, что старая версия будет постепенно выведена из эксплуатации.

## Три интерфейса

| Назначение | Путь |
|---|---|
| Обучение тембра | `POST /api/v3/tts/voice_clone` |
| Запрос статуса | `POST /api/v3/tts/get_voice` |
| Синтез | `POST /api/v3/tts/unidirectional` (потоковый HTTP chunked) |

Host всегда `https://openspeech.bytedance.com`.

### Обучение

```json
{
  "speaker_id": "S_xxxxxxxx",
  "audio": { "data": "<base64>", "format": "wav" },
  "source": 2,
  "language": 0,
  "model_type": 5
}
```

- **Клонирование 2.0 — только при `model_type: 5`.** Если не передать или передать другое значение, обучится 1.0.
- **Тело запроса — один объект `audio`, а не массив `audios`.** В интерфейсе v1 был массив, в v3 это изменили;
  при передаче массива будет ошибка `45000000 add unmapped key audios`.
- Опционально: `text` (текст, соответствующий референсному аудио; сервер проверяет WER, при большом расхождении возвращает `45001109`),
  `enable_audio_denoise` (шумоподавление, снижает сходство),
  `disable_volume_normalization` (отключить нормализацию громкости — громкость синтеза ближе к референсному аудио).
- Возвращается `status`: 0 NotFound / 1 Training / 2 Success / 3 Failed / 4 Active.
  **И при 2, и при 4 можно сразу синтезировать.**
- В ответе `speaker_status` — массив, содержащий сразу две версии, 1.0 и 2.0;
  версия 2.0 — запись с `model_type: 5`, у каждой есть ссылка `demo_audio` для прослушивания, действительная один час.

### Запрос статуса (замер 2026-09-18)

Тело запроса v3 `get_voice` использует единственное число `{"speaker_id":"S_xxxxxxxx"}`, а не массив `speaker_ids`. Несколько слотов запрашиваются по одному, ошибки HTTP нужно явно сообщать, а не считать, что тембра не существует. `koubo.py voices` исправлен соответственно.

### Синтез

```json
{
  "user": { "uid": "koubo" },
  "req_params": {
    "text": "...",
    "speaker": "S_xxxxxxxx",
    "model": "seed-tts-2.0-expressive",
    "tone_fidelity": true,
    "audio_params": { "format": "wav", "sample_rate": 48000, "speech_rate": -20 }
  }
}
```

Ответ потоковый, по одному JSON на строку, аудио лежит в поле `data` фрагментами base64; склеив их, получаете полный файл.

## Два контринтуитивных расположения параметров

1. **`speech_rate` обязательно должен быть внутри `audio_params`.** На верхнем уровне `req_params` он **молча игнорируется** —
   ошибки нет, возвращается 200, аудио нормальное, но скорость речи не меняется ни на йоту.
   По замеру `audio_params.speech_rate = -50` растянул одну и ту же фразу с 10,36 с до 21,53 с (ровно в 2 раза).
   Диапазон `[-50, 100]`, 0 — по умолчанию, 100 = скорость 2.0, -50 = скорость 0.5, линейно.
   Так же молча игнорируется `speed_ratio` (на любом уровне) — это имя параметра из другой продуктовой линейки.

2. **`tone_fidelity` кладётся на верхний уровень `req_params`**, а не в `audio_params`. Действует только для тембров 2.0.

## Частота дискретизации

`sample_rate` поддерживает `[8000, 16000, 22050, 24000, 32000, 44100, 48000]`, **по умолчанию — только 24000**.
Для вклейки обратно в монтажный проект 48k обязательно явно передавайте 48000, иначе звук будет глухим.
`ogg_opus` поддерживает только 48000. Для потоковых сценариев официально рекомендуется pcm, а не wav.

## Прочие ограничения

- **Лимит 10MB для референсного аудио считается по исходному файлу, а не после base64** (по замеру wav на 9,16MB проходит).
  Поддерживаются wav / mp3 / ogg / m4a / aac / pcm, pcm — только 24k моно.
- Текст для синтеза за один раз рекомендуется < 300 иероглифов (около 60 секунд аудио), длинные тексты нужно самостоятельно резать и склеивать.
- На каждый слот тембра — 15 попыток обучения, обучение можно повторять с перезаписью.
- Интерфейс «апгрейда тембра» (`/api/v3/tts/upgrade_voice`) — это только миграция V1→V3,
  **он не может добавить референсное аудио к существующему тембру**. Чтобы сменить референсное аудио, остаётся только переобучить тот же слот.

## Частые коды ошибок

| Код | Значение | Что делать |
|---|---|---|
| `45000000` | Неверные поля тела запроса | Смотрите unmapped key в message |
| `45001122` | `no speaker detected` | В референсном аудио нет голоса. Сначала проверьте средний уровень: ниже -36dB — это практически фоновый шум |
| `45001109` | `WERError` | Переданный `text` не совпадает с содержимым аудио — уберите text или исправьте его |
| `45000030` | `resource not granted` | Сервис, соответствующий этому Resource-Id, не подключён |

## Сеть

`openspeech.bytedance.com` — интерфейс внутри Китая. Если на машине включён socks-прокси,
**одной передачи `proxies=None` в requests недостаточно** — библиотека всё равно читает `ALL_PROXY` из окружения,
что проявляется периодическими `SSL: UNEXPECTED_EOF_WHILE_READING`.
В затронутых окружениях можно настроить `bindings.volcengine.trust_env=false`; по умолчанию соблюдается прокси из окружения, обход не навязывается всем пользователям.

## О том, «сколько референсного аудио скармливать»

В исторических прослушиваниях более длинный чистый референс озвучки звучал ближе к оригиналу, чем тридцать секунд. Это опыт на одном голосе, а не единое значение по умолчанию для всех тембров; ориентируйтесь на прослушивание собственных образцов пользователя и текущие ограничения сервиса.

Я провёл замер с градиентом длительности (вложенные выборки 15/30/60/120/200/400 секунд, по 3 синтеза на каждую ступень),
сравнивая медиану основной частоты и спектральный центроид с оригинальным голосом человека; разница между ступенями (1,7%~8,5%) и
стандартное отклонение между тремя синтезами одной ступени (1,7~9,5) — одного порядка, **по этим двум метрикам победителя не выявить**.

Но это не опровержение — эти две метрики охватывают только высоту и яркость тембра
и **совершенно не охватывают просодию, паузы, дыхание и интонацию**, а именно они — главная составляющая того, «похоже ли это на самого человека».
То, что метрики не видят разницы, не значит, что разницы нет. Решает ухо.
