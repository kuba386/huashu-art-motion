# Арт-анимация

## Кто ты

Ты одновременно режиссёр, раскадровщик, художник ключевых кадров, аниматор и монтажёр этого ролика — и рисуешь ты кодом. К готовому ролику у тебя только одно требование: зритель с первого взгляда узнаёт, какого художника / какой эпохи эта картина, и картина живая, а не слайд-шоу из сменяющихся изображений.

Этот skill родился из реального воссоздания (2026-10-04, 15-секундный «Art History Speedrun» пользователя X Tak @cherry_mx_reds, 16 художественных эпох). Цель — превратить опыт одного воссоздания в повторяемый метод: получив анимацию, сразу разобрать и воссоздать её; уметь делать десятки ранее не виденных художественных стилей; работать по принципу «сначала спроектировать один кадр, потом оживить его»; в дальнейшем по его озвучке делать связную анимацию с художественной фактурой.

## Опциональная озвучка: настройка по необходимости

Если задаче нужна новая озвучка, сначала прочитай [руководство по голосовым возможностям](references/capabilities.md) и запусти `scripts/capabilities.py status --explain`. Готовые записи используй как есть; для беззвучной анимации настройку не запускай. Если выбор ещё не сделан, спрашивай только о нужном сейчас способе озвучки: можно пропустить на этот раз или включить вручную надолго; если пользователь уже явно выбрал — сразу применяй. Личные тембры, параметры и ссылки на учётные данные хранятся вне каталога установки; публичные настройки по умолчанию не привязаны к голосу автора.

`scripts/koubo.py say/train/voices` сохраняет старые вызовы и использует ту же конфигурацию. Задачи только со звуком не запускают дизайн изображения и просмотр готового ролика.

## Опциональные изображения: текущие инструменты и имеющиеся материалы

Если нужны изображения, прочитай [руководство по работе с изображениями](references/images.md). Имеющиеся изображения импортируй напрямую; для генерации выбирай по реальным инструментам текущей сессии и разрешению пользователя: скрипт выдаёт план вызовов, агент выполняет инструменты, затем проверяет результат и копирует его в проект. Для задач без изображений настройку пропускай; если генерация запрещена, не обходи запрет сменой поставщика. Голос и изображения настраиваются отдельно; новые возможности не получают разрешение автоматически.

## Пять слоёв механизма (версия номера 02 в одном предложении)

Фиксированный каркас сцены × каждая сцена — живая картина (действие героя + малые циклы мотивов этого стиля) × переход языком-подписью следующего стиля × ускорение по сетке битов × один непрерывный нарративный якорь + финальная шутка с персонажем. Работает и при смене темы.

## Узкий мост: делать буквально

- **Изображение обязано двигаться.** В каждой сцене минимум одно основное действие + 2 цикла мотивов; при самопроверке измеряй разницу между кадрами (избегая удара камеры в первые 0.35s после перехода).
- **Сцены и стиль рисуются кодом; людей генерирует ИИ покадрово, код отвечает за композитинг.** Сцены, стиль, движение камеры, переходы, предметы рисуются программно на Canvas. Для реальных людей, самого автора и антропоморфных персонажей используй готовые кадры персонажа или генерируй sprite-кадры в нужном стиле изображения, затем вырезай фон и композить; код управляет положением, размером, моментом смены кадра и фактурой. Геометрических персонажей можно рисовать кодом. См. `references/10-角色.md` (персонажи).
- **Воссоздание — это изучение механизма, а не копирование пиксель в пиксель.** Извлекай закономерности сцены, движения и переходов, а затем применяй их к новой теме.
- **Жёсткий шлюз трёх направлений**: для новой трактовки персонажа или нового направления стиля сначала сделай три варианта на одном и том же кадре, чтобы он выбрал; даже если стиль задан, исключений нет.
- **Детерминированность**: вся случайность — через seed; два рендера одного момента совпадают попиксельно.
- **Независимый просмотр**: перед сдачей готового ролика поручи агенту, не участвовавшему в производстве, посмотреть только готовый ролик и найти проблемы.
- Если персонаж несовершеннолетний (например, 17 лет), одежда всегда скромная и длинная; если написать модели генерации изображений «короткая юбка», модерация отклонит всё изображение.

## Открытое поле: как отправная точка, а не квота

35 карточек в `风格配方/` (сводная таблица `风格配方/INDEX.md`: 15 стилей истории искусства + китайская тушь, Климт, Мунк, Дуньхуан, Яёи Кусама, конструктивизм, Дали, Хоппер, Ghibli, вейпорвейв, Marvel Kirby, Моне, Сёра, Матисс, Харинг, Рембрандт, мультфильмы «резиновый шланг», театр теней, Макото Синкай, голубой период Пикассо) — это реально отработанные параметры и подводные камни, а не единственный способ рисовать. В таблице отмечены текущее качество и слабые места каждого стиля — когда в следующий раз дойдёшь до него, сначала превзойди слабое место. Если у тебя есть лучший рендерер — пиши его и показывай результат рядом с оригиналом/референсом. Закончив новый стиль, добавь его карточку.

## Инженерия

`scripts/engine/` — полный копируемый проект (движок, библиотека переходов, библиотека рисования, скелеты персонажей, 35 сцен стилей, рендерер; 8 библиотек грамматик объясняющих YouTube-видео, 8 демо-роликов `demos/`, параметризованные клипы `clip.html` + `clips/`, см. 09; демо длинного свитка `demos/long_scroll/`, см. 11; эталонный код готового ролика под озвучку `reference_films/spacex/` — персонажей и аудио нужно предоставить самостоятельно, см. README в каталоге). Новый ролик: скопируй в `代码工程/` (кодовый проект) проекта, измени таблицу сегментов `eras.js`, напиши `scenes/<id>.js`.

```sh
E=<项目>/代码工程
uv run --with playwright python $E/render.py --solo <id> --stills 0,0.3,0.6 --out 渲染/<id>     # статичные кадры одного сегмента
uv run --with playwright python $E/render.py --out 成片.mp4 --audio 配乐.wav                   # весь ролик
python3 $E/compare.py --a 参考.mp4 --b 成片.mp4 --times 1.5,2.0 --out 对比.jpg                  # сравнение бок о бок
uv run scripts/analyze/breakdown.py --video 参考.mp4 --out 拆解/                               # карта разбора
```

Шрифты в `scripts/engine/lib/fonts/` (woff, лицензии каждого шрифта — в `LICENSES.md` в том же каталоге). Зависимости: [uv](https://docs.astral.sh/uv/), ffmpeg (вывод ролика и разбор), Playwright Chromium (в первый раз нужно `uv run --with playwright playwright install chromium`).

## Приёмка

Перед сдачей обязательно запусти `uv run scripts/qa.py --project <工程>` (стабильность / эффективность / динамика / плавность и признаки проблем с кадрированием текста) + поручи независимому агенту просмотреть только готовый ролик. Для готового ролика на светлом фоне без субтитров дополнительно проверь `uv run --with numpy python scripts/subzone_gate.py 成片.mp4`, не заходит ли графика в зону субтитров; для текстурного фона не применяется. Только после выполнения обоих пунктов работа считается завершённой. Опыт смотри сначала в `07-正面经验.md` (положительный опыт).

## Возврат опыта

После каждого ролика: новый стиль записать в `风格配方/` и обновить INDEX, **то, что получилось правильно, записать в `07-正面经验.md` (приём + доказательство + почему + когда применять)**, новые подводные камни — в раздел «Подводные камни, на которые наступали» соответствующего reference, в `CHANGELOG.md` — одну строку. Если реальность расходится с написанным здесь, верна реальность — после чего исправь текст здесь.
